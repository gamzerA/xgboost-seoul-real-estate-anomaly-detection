# 발전 버전 연구 방법론

`src/train_robust_pipeline.py`는 학회 발표 당시 XGBoost 단일 모델 분석을
재현하는 코드가 아니라, 그다음 연구 단계에서 사용할 모델 선정 및 강건성
검증 파이프라인입니다. 기존 `src/train_xgboost.py`는 비교를 위해 그대로
보존합니다.

## 1. 검증 설계

연도 순서를 지키는 expanding-window 방식을 사용합니다. 2022–2025년 자료가
모두 있다면 다음 순서로 작동합니다.

| 단계 | 학습 자료 | 검증·평가 자료 | 사용 목적 |
|---|---|---|---|
| 모델 선정 1 | 2022년 | 2023년 | 후보 모델 비교 |
| 모델 선정 2 | 2022–2023년 | 2024년 | 후보 모델 비교 |
| 최종 평가 | 2022–2024년 | 2025년 | 선정 모델의 일반화 성능 보고 |

최종 연도는 모델 선정에 사용하지 않습니다. 후보 모델은 2023년과 2024년
시간 검증의 평균 RMSE가 가장 낮은 순서로 선정하며, 동률이면 평균 MAE를
사용합니다. 최종 연도에서 다른 후보 모델을 다시 비교하여 모델을 바꾸지
않습니다.

## 2. 비교 모델

- `median_baseline`: 설명 변수를 사용하지 않는 중앙값 기준선
- `ridge`: 단순한 선형 관계를 확인하는 정규화 회귀 기준선
- `random_forest`: 비선형성과 변수 간 상호작용을 포착하는 bagging 모델
- `hist_gradient_boosting`: scikit-learn의 histogram 기반 boosting 모델
- `xgboost`: 학회 발표 모델과 직접 연결되는 boosting 모델

모든 후보는 동일한 입력 변수와 시간 폴드를 사용합니다. 숫자형 변수의
결측치는 학습 폴드의 중앙값으로 처리합니다. 범주형 변수는 학습 폴드 내부의
교차적합 Target Encoding을 사용하여 임의의 숫자 순서를 부여하지 않습니다.
미래 연도에서 처음 나타난 단지나 법정동은 학습 폴드의 전체 목표 평균으로
처리됩니다. 따라서 미래 자료의 범주나 가격 정보가 학습 전처리에 유입되지
않습니다.

## 3. 강건성 검증

최종 선정 모델에 다음 검증을 수행합니다.

1. **최종 연도 홀드아웃**: R², MAE, RMSE, Median AE, WAPE를 계산합니다.
2. **Bootstrap 신뢰구간**: 최종 연도 R²·MAE·RMSE의 95% 구간을 계산합니다.
3. **하위 집단 분석**: 자치구, 전용면적 구간, 실제가격 사분위별 지표를
   저장하여 평균 성능이 특정 집단의 큰 오류를 가리는지 확인합니다.
4. **Seed 민감도**: 여러 난수 seed로 다시 적합하여 최종 지표의 변화를
   확인합니다.
5. **후보 안정성**: 각 seed에서 선정된 상위 N개 후보의 Jaccard 일치도를
   계산합니다.
6. **임계값 민감도**: 상위 0.1%, 0.5%, 1%, 2%에서 후보 수와 오차 특성이
   어떻게 달라지는지 저장합니다.
7. **Permutation importance**: 최종 홀드아웃에서 각 변수를 섞었을 때의
   RMSE 증가량을 계산해 모델 종류와 무관하게 변수를 비교합니다.

## 4. 이상거래 후보 점수

2023년 거래는 2022년으로 학습한 모델, 2024년 거래는 2022–2023년으로
학습한 모델, 2025년 거래는 2022–2024년으로 학습한 모델로 예측합니다.
따라서 점수가 계산된 거래는 어느 것도 자기 자신의 가격을 학습에 제공하지
않습니다. 최초 연도는 그보다 앞선 학습 자료가 없으므로 후보 점수를 만들지
않습니다.

가격 규모에 따른 분산 차이를 줄이기 위해 다음 로그잔차를 사용합니다.

```text
로그잔차 = log(실제가격) - log(예측가격)
강건성이상점수 = |로그잔차 - 해당 연도 중앙값| / (1.4826 × 해당 연도 MAD)
```

절대잔차와 오차율도 함께 저장합니다. 이 점수는 가격 패턴에서 멀리 떨어진
거래의 **추가 검토 우선순위**일 뿐, 불법·부정 거래의 판정값이 아닙니다.

## 5. 주요 산출물

`results/advanced/generated/tables/`에 다음 파일이 만들어집니다.

| 파일 | 내용 |
|---|---|
| `temporal_fold_metrics.csv` | 모델·검증연도별 성능 |
| `model_comparison.csv` | 시간 검증 평균 및 모델 선정 순위 |
| `final_holdout_metrics.csv` | 선정 모델과 참고용 중앙값 모델의 최종 연도 성능 |
| `bootstrap_confidence_intervals.csv` | 최종 지표 95% 신뢰구간 |
| `subgroup_metrics.csv` | 지역·면적·가격 구간별 성능 |
| `seed_sensitivity.csv` | seed별 최종 연도 성능 |
| `seed_candidate_stability.csv` | seed별 상위 후보 Jaccard 일치도 |
| `threshold_sensitivity.csv` | 후보 비율별 임계값 민감도 |
| `permutation_importance.csv` | 최종 연도 변수 중요도 |
| `out_of_time_predictions.csv` | 시간 순서를 지킨 거래별 예측과 오차 |
| `anomaly_candidates.csv` | 강건성이상점수 상위 N개 검토 후보 |

`run_summary.json`에는 선택 모델, 최종 지표, 데이터 파일 해시와 라이브러리
버전이 기록됩니다. 거래별 결과는 개인정보·용량·오해 가능성을 고려해 Git에
커밋하지 않습니다.

## 6. 남아 있는 한계

- 실제 불법·부정 거래 라벨이 없으므로 Precision, Recall 같은 탐지 성능을
  보고할 수 없습니다. 전문가 검토 표본이나 공신력 있는 라벨이 필요합니다.
- 금리, 교통, 학군, 정비사업 등 외부 설명 변수가 아직 포함되지 않았습니다.
- 시간 기반 검증은 시장 국면 변화에 대한 근거를 강화하지만 미래의 모든
  구조적 변화를 보장하지는 않습니다.
- 단지명이 바뀌거나 표기 방식이 달라지는 데이터 품질 문제는 별도의 정규화가
  필요합니다.

따라서 결과를 발표할 때는 “이상거래 탐지 완료”가 아니라 “가격모형의
out-of-time 잔차를 이용한 검토 후보 선별”이라고 표현해야 합니다.
